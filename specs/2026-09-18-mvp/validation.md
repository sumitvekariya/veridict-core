# Validation: MVP, verification attestations in git

Implementation is complete and ready to merge when all of the following hold.

## Automated

- [ ] `.venv/bin/pip install -e .[dev]` exits 0
- [ ] `.venv/bin/pytest` exits 0 with no failures
- [ ] `.venv/bin/mypy src/veridict --ignore-missing-imports` exits 0
- [ ] `.github/workflows/ci.yml` is green on the `mvp` branch

Specific coverage required:

- [ ] DSSE PAE matches the specification's golden vector
- [ ] A tampered payload, an unknown key and a replayed envelope are each
      rejected by verify
- [ ] Two independent appends to the notes ref merge with `cat_sort_uniq`
- [ ] crosshair counterexample `false when calling ...` is parsed into
      `evidence.counterexamples`
- [ ] A commit with no authorship attestation and no trailer is treated as
      `agent` by the default policy
- [ ] `verify` exits 0 on a met policy, 1 on an unmet one, 2 on a missing
      policy file

## Manual

- [ ] `veridict keygen` writes a key outside the repository and prints a
      keyid; the keyid pasted into `.veridict/policy.toml` is accepted
- [ ] `veridict attest --adapter python --sign key` on this repository's
      `HEAD` appends three note lines visible with
      `git notes --ref=veridict show HEAD`
- [ ] `veridict verify HEAD` passes; editing one note line by hand makes it
      fail with a signature error naming the line
- [ ] `veridict hook install` then a commit inside an agent session carries
      `Assisted-by:`; the same commit outside one does not
- [ ] Live run: the demo repository's `veridict.yml` attest job is green,
      `git ls-remote origin 'refs/notes/*'` lists `refs/notes/veridict`, the
      verify job on a pull request reports the verdict in the step summary,
      and the stored bundle names the workflow identity
- [ ] A fresh clone of the demo repository plus `veridict fetch` and
      `veridict verify main` reproduces the verdict with no forge API

## Trust-boundary check

- [ ] No private key material in either repository; `*.pem` ignored
- [ ] The action requests only `id-token: write` and `contents: write`
- [ ] Verify in key mode makes no network calls (run with networking
      disabled once)
- [ ] `grep -r github src/veridict` finds only the authorship trailer
      heuristics and the OIDC issuer string, no API calls

## Definition of done

Roadmap Phases 1 to 4 ticked, with the evidence-ref item moved to Phase 5;
`CHANGELOG.md` generated by the changelog skill; branch `mvp` merged into
`main` and deleted; no debug prints, no TODOs in `src/`.
